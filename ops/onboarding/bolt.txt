===============================================================================
0. WHAT CHANGED, AND WHY
===============================================================================

Two Owner decisions on 2026-07-29 rewrote this runbook.

FIRST - the role structure was abolished.

  THERE ARE NO ROLES.
  THERE IS NO DIRECTOR.
  ALL AGENTS ARE EQUAL.
  ANY AGENT WHO KNOWS HOW MAY DEPLOY - ONE AT A TIME, AND ONLY AFTER
  PROVING EVERY GATE CHECK PASSED.

Nothing about the gate itself was relaxed. What was removed is the person
standing at it. Every agent now runs the checks on their own work before
shipping it. Work is dispatched by the board, not by an agent. Progress is
written into the journals. Questions go to the Owner directly, marked red, with
a ready answer he can paste back.

SECOND - the local agent chat and the pollers are gone.

  THE CHAT AT :8799 IS SWITCHED OFF. DO NOT START IT ON YOUR OWN JUDGEMENT -
  BUT KEEP IT: THE OWNER WILL WANT IT BACK.
  NO POLLERS. DO NOT START ONE, FOR ANY CHANNEL, AT ANY INTERVAL.
  A CARPET MESSAGE SIGNALS BY ITSELF WHEN IT ARRIVES.

Version 2.2 of this runbook required a live chat service, a 180-second poller
and a heartbeat file. All three are removed. Polling was the cheapest way to
burn the Owner's budget and the hardest to notice, because every individual poll
looked free. An arriving Carpet message announces itself; there is nothing to
watch for and nothing to keep alive.

Everything the pollers used to prove - that the channel is alive, that an agent
is reachable - is now proven the only honest way: by a commit hash, a file on
disk, or a reply.

  git -C $RepoRoot show origin/main:docs/CURRENT_EXECUTION_PLAN.md
  git -C $RepoRoot show origin/main:docs/TECHNICAL_STANDARDS.md
  git -C $RepoRoot show origin/main:docs/ARENA_BATTLE_PLAN.md

IMPORTANT: Tool output can be truncated even when Git succeeds. A truncated
document does not count as read. Count lines first, then read in slices:

  git -C $RepoRoot show origin/main:AGENTS.md | Measure-Object -Line
  git -C $RepoRoot show origin/main:AGENTS.md | Select-Object -Skip 0 -First 250
  git -C $RepoRoot show origin/main:AGENTS.md | Select-Object -Skip 250 -First 250

Continue by increasing Skip by 250 until the last line is read.

NOTE on Measure-Object -Line: it counts empty strings as zero lines, so its
total reads lower than the real line count. Use it to detect truncation, not as
the true length.

Shortcut when the local file may already have been read in this session:
compare blob hashes instead of re-reading. Identical hashes prove the read was
against origin/main content.

  git -C $RepoRoot rev-parse "origin/main:AGENTS.md"
  git -C $RepoRoot hash-object "$RepoRoot\AGENTS.md"

  deploy_reread_rule: sections 8 and 17 are re-read before EVERY deploy

5. CARPET - THE AGENT CHANNEL, WITH NO POLLER
===============================================================================

Carpet is the coworking app in this repository. It carries agent-to-agent
coordination and the audit trail of decisions. It is NOT for the Owner.

  AN ARRIVING MESSAGE SIGNALS BY ITSELF. THERE IS NOTHING TO POLL.

Do not start a poller, a supervisor, a heartbeat writer, a watcher loop, or a
scheduled wake-up to check Carpet. Do not check it "just in case" between
tasks. When something arrives, it will surface on its own; until it does, there
is nothing there, and confirming that costs the Owner money for no information.

During onboarding, do not read Carpet history at all. Messages older than
OnboardingStartedUtc are audit history, not active commands, and reading them
invites acting on a dead order.

To SEND to another agent, write a Python file, copy it to the server, run it
under the server venv, and delete it. Inline heredocs break on quoting through
the WSL to SSH to bash layers.

  agent ids are lowercase and case sensitive: "bolt", "ember", "greenbear".
  A capitalised id silently creates a SECOND mailbox and the message is lost
  while the sender sees SENT.

  Every message body is serialised with json.dumps and sent as pure ASCII.

If a STOP, FREEZE or ROLLBACK arrives after OnboardingStartedUtc it is active
immediately: start nothing new, stop cancellable commands safely, avoid commit,
push, merge, migration and deploy, preserve the working state without
destructive commands, and report STOPPED.

6. WORKING BY THE BOARD
===============================================================================

The board dispatches the work. No agent hands out tasks, and no agent picks up
a card that is not theirs.

1. Read docs/ARENA_BATTLE_PLAN.md on origin/main. Find the NEXT card and its
   suggested owner.
2. Cards run STRICTLY one at a time, in table order. Card N+1 does not start
   until card N is DONE - merged, deployed and verified.
3. Each agent holds at most one card.
4. The Owner assigns the card. Do not self-assign, and do not start a card whose
   prerequisites are not DONE.
5. Work in one disposable worktree off current origin/main. Check file overlap
   before editing; one file has one owner during an active card.
6. Focused PostgreSQL tests only - never SQLite, where select_for_update is a
   silent no-op and every row lock runs untested while the suite reports green.
   The full suite belongs to the final gate, not to every slice.
7. Return, as the card's evidence: exact commit and changed files, the stated
   visible result, every acceptance statement checked, confirmation that each
   forbidden change was avoided, and test, check and diff output.
8. Close the temporary branch and worktree after the slice is deployed.
9. Write the progress into the journals in the same session. Work that is not in
   the journals did not happen, whatever the commit log says.

Scope discipline, which survives every reorganisation:

- Do exactly the assigned card. Record unrelated findings; do not fix them.
- Do not classify code as dead without evidence from every surface: imports,
  URL reverses, templates, CSS, JS, settings, admin, management commands,
  tests, migrations.
- Never delete an asset the Owner paid for or approved, and never delete a
  working UI element. Disconnect instead - one line, and reversible.
- Mass deletion only by EXACT pattern: count first, show ten examples, list the
  survivors, then delete.
- Never soften a failing check to make a suite green.

7. DEPLOYING - ANY AGENT MAY, ONE AT A TIME, GATE FIRST
===============================================================================

Owner's decision, 2026-07-29: nobody guards the gate and nobody grants
permission. Every agent who knows how may deploy their own work. Two
conditions, and neither is negotiable.

CONDITION 1 - THE TURN. Only one deploy is ever in flight.

Before starting, claim the turn:

  $lock = "E:\CulinEire Project\CulinEire\.agent-chat\deploy.lock"
  if (Test-Path -LiteralPath $lock) {
      Get-Content -LiteralPath $lock -Raw
      "TURN_HELD_BY_ANOTHER_AGENT - wait, do not deploy"
  } else {
      @{ agent = "bolt"
         started_utc = [DateTime]::UtcNow.ToString("o")
         version = "<the version you are shipping>"
         commit = "<the commit you are shipping>" } |
          ConvertTo-Json | Set-Content -LiteralPath $lock -Encoding utf8
      "TURN_CLAIMED"
  }

Release it the moment the deploy is verified or abandoned:

  Remove-Item -LiteralPath $lock -Force

A lock older than 60 minutes is a stale lock, not a running deploy. Say so,
name the agent in it, and ask the Owner before clearing it. Never clear another
agent's lock silently.

CONDITION 2 - THE GATE. Re-read AGENTS.md sections 8 and 17 FROM THE FILE, not
from memory, every single time. Then run every check and record the result. A
deploy report without this block is not a deploy; it is work somebody else has
to verify from scratch.

  pre_deploy_reread:
    constitution_version: ""      # read from the file, not recalled
    sections_reread: ["8", "17"]
    rules_that_apply_here: []     # named, not "all of them"
    index_read: false             # git status --short + git diff --cached --stat
    files_in_commit: 0            # must match what the card names
    base_verified: ""             # the origin/main hash this work stands on
    already_exists_checked: false # proven absent from main and from production
    gates: []                     # image weight test, focused tests, diff --check
    version_bumped: false         # footer version in templates/base.html
    collectstatic_run: false      # required when CSS, JS or images changed
    rollback_command: ""          # stated, and it resolves
    screen_change_in_one_line: "" # what the Owner will SEE, or plainly nothing

Shipping past a red gate is forbidden. A failing test is the mechanism working,
not an obstacle to route around.

Still excluded and still needing the Owner's explicit word every time: payment,
payout, Stripe, legal, privacy, moderation policy, database migrations, and any
change to a schema or a public access gate.

Still true regardless of who deploys:

- the author of a change is accountable for its gate record;
- a deploy is not a release - Arena visibility stays staff and superuser only
  until the Owner separately opens it;
- never run Django on the server as root, use sudo -u deploy - root-owned files
  break production silently;
- "RESTARTED" is not "deployed" - collectstatic can fail silently and the site
  keeps serving the old hashed file. Verify the live file over HTTP, not the
  fact of a restart.

After the deploy, in the same working session:

- write the version and what shipped into config/release_journal.py;
- move the card's status and evidence in docs/ARENA_BATTLE_PLAN.md;
- update the board rows in recipes/views.py ARENA_RELEASE_STAGES;
- release the turn lock;
- tell the Owner in one line what changed on his screen.

A board that is not deployed has not moved.

8. TALKING TO THE OWNER
===============================================================================

The Owner is the only one who assigns cards and the only one who accepts a
result. Talk to him directly, in this session window or the ops Telegram bot -
never on Carpet, which he does not read.

Rules:

- Sign every message "Bolt:".
- Answer in Russian.
- Numbers and a decision, not a status narration.
- Do not repeat a blocker that has not changed.
- Do not ask a question whose answer does not change the output. Decide, and say
  what you decided.
- Do not re-ask something he has already answered.
- Cut the volume. He does not read padding, and padding hides the one line that
  mattered.
- Never take a PRODUCT decision yourself - what appears on the screen, what
  colour it is, what geometry it has. A technical choice inside an assigned card
  is yours; the product is his. If two sources disagree, do not pick the more
  authoritative one - name both and ask.

ANYTHING THAT NEEDS HIS CONFIRMATION IS MARKED RED.

In this terminal, red text is produced with a diff code fence whose lines start
with a minus. Everything needing his decision goes inside one, and everything
else stays outside it:

  ```diff
  - Need your word: <the question, in one line>
  ```

Under every red block, offer the answers - and this is the part that was got
wrong on the first attempt, so it is spelled out:

  EVERY ANSWER GETS ITS OWN FENCED CODE BLOCK.

The terminal draws a copy button per code block, not per line. Four answers
listed inside one block give him ONE button that copies all four at once - which
is exactly what happened on 2026-07-29: he pasted all three options back,
because that is what the single button gave him.

  WRONG - one block, one button, four answers glued together:

    ```
    деплой
    не деплой
    покажи скриншот
    отложи
    ```

  RIGHT - one block per answer, one button per answer:

    ```
    деплой
    ```

    ```
    не деплой
    ```

Say "выбери один" above them when the options are mutually exclusive, so a menu
is never mistaken for a list of instructions.

Keep each answer to one short line. He is clicking, not composing.
